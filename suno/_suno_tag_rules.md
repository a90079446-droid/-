# Suno 공통 작성 규칙 (조사 반영, 2026-11-25)

> 데일리 지침·프로젝트 지침·곡 분석 프롬프트 모두 이 규칙을 따른다. 근거: `suno_guide_research.md`
> 이 규칙과 다른 문서가 충돌하면 이 규칙이 이긴다 (최신 사용자 피드백은 이 규칙보다 우선).

## 가사 칸 태그
1. 태그는 줄 하나에 따로 쓴다. 가사 줄 안에 태그를 넣지 않는다.
2. 섹션 태그 하나에 붙는 지시는 **2~3개까지** (쉼표로 구분한 묶음 기준). 구조·에너지 지시를 먼저, 보컬 지시는 뒤에.
3. **반복되는 사비(Chorus)·프리코러스·훅은 태그를 글자 그대로 똑같이** 쓴다. 에너지 상승은 핵사비(Final Chorus) 태그에서만 준다.
   - 이전 규칙 "첫 사비는 에너지 절반"은 이 규칙으로 대체한다 (첫 사비와 반복 사비는 같은 태그, 핵사비만 더 크게).
4. 연주만 나오는 구간은 `[Instrumental, 4 bars]`, `[Instrumental, 8 bars]`처럼 마디 수를 적는다.
5. 섹션 이름은 항상 영어 대괄호.

## 스타일 칸
1. 장르(+서브장르) 하나를 맨 앞에. 장르를 여러 개 쌓지 않는다.
2. 순서: 장르 → 무드 → BPM·박자·키 → 드럼·베이스 → 악기 2~3개 → 보컬(성별 명시: solo male vocal) → 믹스 → 구조 한두 마디
3. 길이: 데일리형·레퍼런스 곡 **250~400자**, 프로젝트형(문장형) **300~450자**. 1,000자를 넘기지 않는다.
4. 부정어("no ~")는 스타일에 쓰지 않고 제외 스타일 칸으로 보낸다.
5. 구조 태그([Verse] 등)는 스타일에 쓰지 않는다.

## 제외 스타일 칸
- 8~12개. 빼고 싶은 것은 전부 여기에 (공식 Exclude 기능).

## 설정값
- 기이함: 공식 기준 50%가 '보통'. 우리 기본 15~35%는 안전 쪽으로 의도한 값.
- 스타일 영향: 70~85%.
- 세 번째 슬라이더: 공식 이름 Audio Influence는 오디오 업로드 때만 나온다. 만들기 탭의 '다양성'은 정체 미확인 → "지금 쓰시는 값 유지" 또는 35~45%로 표기.

## 수정 요령 (v6)
- 결과 중 일부(예: 후렴)만 마음에 안 들면 곡 전체를 다시 만들지 말고 v6 부분 수정으로 그 구간만 고친다.

## 검수
- `python3 suno/tools/check_suno.py <파일.md>` 로 태그 지시 개수, 반복 사비 태그 동일 여부, 가사 줄 안 태그, 스타일 길이, 스타일 속 부정어를 확인한다.
