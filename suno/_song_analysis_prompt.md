# 레퍼런스 곡 분석 → Suno 곡 제작 프롬프트 (v2, 2026-11-25: 조사 반영 태그·스타일 규칙)

> 사용법: 아래 [입력]만 채워서 이 문서 전체를 그대로 주면 된다. 비우면 기본값으로 진행한다.
> 우선순위: 최신 사용자 피드백 > 이 문서 > 데일리 지침(`_suno_trend_prompt.md`) / 프로젝트 지침(`project_pop/_brief.md`)

## [입력]
- 레퍼런스: 유튜브 링크 또는 "가수 – 곡명" (여러 곡이면 줄마다 하나, 믹스 영상이면 설명란 곡 목록을 붙여 넣기)
- 오디오 파일: (선택) mp3·wav를 올리면 직접 측정한다. 없으면 자료 기반으로 분석한다
- 만들 개수: 5 (비우면 5)
- 결과물: 완성곡(제목·가사·스타일·제외·설정값) / 스타일만 (비우면 완성곡)
- 형식: 데일리형 / 프로젝트형 / 섞기 (비우면 섞기: 1곡만 프로젝트형)
- 보컬: 솔로 남성, 저음~중음, 진성 (비우면 이 값)
- 가사 언어: 영어 100%
- 꼭 넣을 것 / 빼고 싶은 것: (자유)

---

## 역할
1. **음악 분석가**: 원곡에 실제로 쓰인 소리를 근거와 함께 뜯어본다. 추측은 추측이라고 쓴다.
2. **프로듀서·작사가**: 분석 결과를 실존 이름 없이 사운드 언어로 옮기고, 원곡의 악기·박자·조성·템포를 살린 오리지널 곡을 만든다.

---

## 1단계. 곡 확인
- 유튜브 링크면 공개 정보(oEmbed)로 제목·채널을 확인한다.
- 유튜브가 다운로드나 페이지 열람을 로봇 확인으로 막으면 **우회하지 않는다.** 그 사실을 밝히고 자료 기반으로 간다.
- 믹스·플레이리스트 영상인데 곡 목록을 못 얻으면 사용자에게 설명란 곡 목록을 붙여 달라고 요청한다.

## 2단계. 자료 수집 (곡마다, 출처 필수)
아래 순서로 찾고, 항목마다 출처와 날짜를 붙인다. 출처끼리 다르면 둘 다 적고 무엇을 택했는지 이유를 쓴다.
1. **Wikipedia API** (`action=parse&prop=wikitext`): 장르, 길이, 발매일, 프로듀서
   - **Credits and personnel**: 누가 어떤 악기를 연주했는지 → 실제 악기 목록의 1순위 근거
   - **Composition / Background**: 키, 템포, 박자, 코드 진행, 녹음 과정(예: 드럼 루프로 시작, 템포를 올림)
2. **BPM·키 데이터베이스**: Tunebat, SongBPM, Musicstax, Music Gateway, AcousticBrainz, 노래방 반주(원키·원템포 표기), 악보 사이트(원조성)
3. **코드·멜로디**: Hooktheory(진행, 조성, 멜로디 음역), 코드 사이트
4. **리뷰·인터뷰**: 음색, 편곡, 보컬 표현 묘사 (Pitchfork, Billboard, NPR, Stereogum, 전문 매체, 프로듀서 인터뷰)
5. **오디오 파일이 있으면** 로컬에서 직접 측정하고 끝나면 파일을 지운다: BPM, 키, 박자, 구간별 에너지 곡선, 서브베이스 비중, 음량(LUFS), 후렴 첫 등장 시점

## 3단계. 분석 시트 (곡마다 세로 목록, 각 줄에 출처)
- **템포**: BPM, 하프타임·더블타임 여부, 스윙·셋잇단 여부
- **박자**: 4/4, 3/4, 6/8 등
- **조성**: 키, 장·단조, 대표 코드 진행(코드 이름만, 멜로디 복사 금지), 마지막 후렴 전조 여부
- **실제 악기**: 크레딧과 녹음 이야기에 나온 악기를 그대로 적는다 (예: 피아노, 베이스, 기타, 키보드, 드럼 루프)
- **드럼**: 패턴(스윙, 포온더플로어, 브레이크비트, 브러시 등)과 질감
- **베이스**: 라이브·신스·808, 연주 방식
- **보컬**: 음역, 전달 방식(속삭임, 벨팅, 랩, 레가토), 더블링·화음, 원곡의 고음·가성 사용 여부
- **구조**: 길이, 인트로 길이, 후렴 첫 등장, 브릿지·드롭 유무, 대비 장치(조용한 벌스 → 터지는 후렴 등)
- **믹스**: 깨끗함·거침, 공간감, 보컬 위치
- **가사 주제**: 태도로 요약 (문장 인용 금지)
- **확인 못 한 항목**: 따로 모아서 적는다

## 4단계. Suno로 옮기는 규칙
### 원곡을 지키는 것 (모든 곡 공통)
- **템포**: 원곡 BPM ±4 안에서 쓴다. 130~140대는 하프타임 표기 규칙을 따른다
- **박자**: 원곡 박자를 그대로 쓴다 (3/4면 "3/4 waltz feel", 6/8면 "6/8 sway")
- **조성**: 원곡 키 또는 같은 음계를 공유하는 짝 조(나란한조)를 쓴다. 장·단조 성격은 바꾸지 않는다
- **악기**: 원곡 실제 악기 중 2~4개를 반드시 스타일에 넣는다. 원곡에 없는 장르 악기를 주인공으로 세우지 않는다
- **대비 장치**: 원곡의 핵심 장치(예: 조용한 벌스와 터지는 후렴, 연주 드롭)를 살린다

### 바꾸는 것
- **보컬**: 기본값(솔로 남성, 저~중음 진성, 더블링)으로 바꾼다. 원곡이 가성·고음이면 진성 벨팅으로 옮기고 가성은 제외에 넣는다
- **보컬 찹**: 원곡 드롭이 보컬 찹이면 원곡 악기 중 하나(신스 리드, 기타 등)로 대신한다
- **언어**: 영어 100%

### N개 버전 나누기 (기본 5개)
장르를 갈아타지 않는다. 같은 악기·박자·조성 안에서 아래 축으로만 바꾼다.
1. **원곡 결**: 가장 가깝게 (편곡 밀도와 에너지 곡선까지)
2. **어쿠스틱·스트립다운**: 원곡 악기 중 1~2개만 남긴 미니멀 버전
3. **데일리 무드**: 어른스럽고 시크하게, 드럼·베이스는 건조하게
4. **프로젝트형**: 벌스는 서브베이스를 빼고 후렴에서 서브베이스와 큰 드럼을 터뜨림 (원곡 악기 유지)
5. **에너지 업**: 같은 템포에서 드럼과 베이스를 키우고 마지막 후렴은 전조
- 사용자가 다른 장르 변주를 원하면 그때만 장르를 바꾼다.

### 스타일 작성 (영어)
- 순서: `장르·서브장르, 무드, BPM(+박자), 키, 드럼, 베이스, 원곡 실제 악기 2~4개, 보컬 설정, 보컬 전달 방식, 믹스, 구조 지시, English lyrics`
- 길이 250~400자 (프로젝트형 300~450자). 실존 가수·곡·프로듀서 이름 금지. 부정어는 제외 스타일로
- 프로젝트형은 문장형 편곡 설명으로 쓴다

### 제외 스타일
- 8~12개. 기본: falsetto, ad-libs, female vocals, (해당 시) pitched vocal chops, 원곡과 다른 언어
- 원곡이 잘못 흘러가기 쉬운 방향을 넣는다 (예: R&B면 trap 808, 발라드면 musical theater)

### 설정값
- 원곡 결·데일리형: 기이함 25~35%, 스타일 영향 70~80%, 다양성 35~45%
- 프로젝트형: 기이함 15%, 스타일 영향 85%, 다양성 지금 값 유지

## 5단계. 가사
- **데일리형**: Intro(연주) → V1 6줄 → Pre 2줄 → 사비 4줄 → V2 6줄 → 사비 → 브릿지 4줄 → 핵사비 → Outro. 벌스 줄당 5~7단어, 브릿지 줄당 4~7단어, 사비 첫 줄 4~7단어 훅. 핵사비는 첫 줄 그대로, 마지막 줄만 새 말. 원곡에 드롭이 있으면 사비 뒤와 핵사비 뒤에 연주 드롭 태그를 넣는다
- **프로젝트형**: `project_pop/_brief.md`의 기본형 (Intro 2줄, V 8줄·8~10단어, Pre 4줄, 사비 8줄·4~6단어, Breakdown 1줄, 브릿지 단타, 핵사비 키업, Outro 수미상관)
- 길이: 원곡 길이 ±20초. BPM으로 마디 수를 계산해 맞춘다 (1마디 = 박자 수 × 60 ÷ BPM 초)
- 주제: 원곡의 정서를 출발점으로 하되 가사·멜로디·제목 문구·핵심 소재는 가져오지 않는다
- 금지어: neon, shadow, midnight, dark, static, echo, fade
- 섹션 태그마다 원곡 실제 악기 이름으로 편곡 지시를 2~3개 붙인다 (예: `[Verse 1: Fingerpicked acoustic guitar only, quiet]`). 반복 사비 태그는 글자 그대로 동일, 에너지 상승은 핵사비 태그에서만
- 공통 규칙 `suno/_suno_tag_rules.md`를 따르고 `suno/tools/check_suno.py`로 검수

## 6단계. 검수 (스크립트로 확인, 실패하면 고쳐서 다시)
- 줄 수·줄당 단어 수, 핵사비 첫 줄 = 사비 첫 줄, 금지어, 원곡 제목 문구 미포함
- 프로젝트형은 `project_pop/check_project.py`로 기존 곡과 겹치는 문장까지 확인
- 스타일에 원곡 템포(±4)·박자·키·실제 악기 2개 이상이 들어갔는지

## 7단계. 출력
1. **분석 요약**: 3단계 시트를 6~10줄로, 각 줄에 출처. 확인 못 한 항목 따로
2. **원곡 → Suno 대응표**: 템포 / 박자 / 키 / 실제 악기 → 스타일 표현
3. **곡마다 Suno 입력**: ① 제목 ② 가사 ③ 스타일 ④ 제외 스타일 ⑤ 기이함 ⑥ 스타일 영향 ⑦ 다양성
4. **Copy 버튼 페이지**로 발행: md를 `suno/tools/build_page.py`로 변환해 아티팩트로 올리고 링크를 준다
5. 마지막에 곡별 한 줄 요약(제목 · 방향 · BPM · 박자 · 키 · 한 줄 이야기)과 출처 링크 목록

## 금지 사항
- 실존 가수·곡·프로듀서 이름을 스타일에 넣기
- 원곡 가사·멜로디·시그니처 훅·제목 문구 복사
- 확인 안 한 수치를 사실처럼 쓰기
- 유튜브 로봇 확인·다운로드 차단 우회
- 원곡 악기와 무관한 장르로 바꾸기 (요청 시 제외)
